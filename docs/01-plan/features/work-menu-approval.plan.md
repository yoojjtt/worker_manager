# 업무관리 메뉴 + 결재요청 기능 Plan

## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | 하단 3탭 메뉴 + 업무관리 메뉴 + 결재요청(OCR 지급서) |
| 작성일 | 2026-05-24 |
| 예상 기간 | 2~3일 |
| 작업자 | 유종태 |

### Value Delivered

| 관점 | 내용 |
|------|------|
| Problem | 관리자가 지급서를 수기로 작성하고 결재 프로세스가 오프라인으로 진행됨 |
| Solution | 사진 촬영 → OCR 자동 파싱 → 수정 → 저장 → 결재요청까지 모바일에서 완결 |
| Function UX Effect | 사진만 찍으면 거래처/금액 자동 입력, 터치 몇 번으로 결재요청 완료 |
| Core Value | 지급서 처리 시간 단축, 결재 프로세스 디지털화, 현장에서 즉시 처리 가능 |

## Context Anchor

| Key | Value |
|-----|-------|
| WHY | 현장에서 발생하는 지급서를 모바일로 즉시 처리하고 결재 프로세스를 진행해야 함 |
| WHO | 관리자(MANAGER) 앱 사용자 (현장 관리자, 본사 관리자) |
| RISK | OCR 파싱 정확도, 대용량 이미지 업로드 시간, 네트워크 불안정한 현장 환경 |
| SUCCESS | 사진→OCR→수정→저장→결재요청 플로우 완성, 결재 목록 조회 가능 |
| SCOPE | 하단 3탭 메뉴, 업무관리 메뉴(4개), 결재요청 CRUD + 목록. QR/안전보고서/작업추가는 placeholder |

## 1. 요구사항

### 1.1 핵심 기능

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| F-01 | 하단 메뉴바 3탭 | 홈 / 업무관리 / 내정보 BottomNavigationBar | 필수 |
| F-02 | 업무관리 메뉴 화면 | QR생성, 안전보고서, 작업추가, 결재요청 4개 아이콘 그리드 | 필수 |
| F-03 | 결재요청 — 사진 업로드 | 카메라 촬영 / 갤러리 선택 → OCR 파싱 | 필수 |
| F-04 | 결재요청 — 자동 입력 | OCR 결과로 거래처명, 계좌번호, 금액 등 자동 채움 | 필수 |
| F-05 | 결재요청 — 수정/저장 | 사용자가 수정 후 저장 (현장/계정과목/거래처 드롭다운 선택) | 필수 |
| F-06 | 결재요청 — 결재요청 | 저장된 지급서에 결재요청 실행 | 필수 |
| F-07 | 결재요청 목록 | 내가 요청한 결재 목록 조회 (상태별 필터, 페이징) | 필수 |
| F-08 | QR생성 | Placeholder 화면 | 낮음 |
| F-09 | 안전보고서 | Placeholder 화면 | 낮음 |
| F-10 | 작업추가 | Placeholder 화면 | 낮음 |

### 1.2 API 매핑

| 기능 | Server API | Method |
|------|-----------|--------|
| OCR 파싱 | `/api/vision/invoice/parse` | POST (multipart) |
| 지급서 저장 | `/api/vision/invoice/save` | POST |
| 지급서 수정 | `/api/vision/invoice/update` | PUT |
| 지급서 상세 | `/api/vision/invoice/detail` | POST |
| 지급서 목록 | `/api/vision/invoice/list` | POST |
| 지급서 삭제 | `/api/vision/invoice/delete` | POST |
| 결재요청 | `/api/vision/invoice/request` | POST |
| 결재이력 | `/api/vision/invoice/approvalHistory` | POST |
| 현장 목록 | `/api/LB/hyunjang/hyunjangRead` | POST |
| 계정과목 목록 | `/api/LB/accounting/category/all` | POST |
| 거래처 목록 | `/api/LB/accounting/partner/findAll` | POST |

### 1.3 결재 프로세스 흐름

```
[사진 촬영/선택]
  → OCR 파싱 (POST /api/vision/invoice/parse)
  → 결과로 폼 자동 채움
  → 사용자 수정 (현장/계정과목/거래처 드롭다운, 금액 수정 등)
  → 저장 (POST /api/vision/invoice/save) → status: DRAFT
  → 결재요청 (POST /api/vision/invoice/request) → status: REQUESTED
```

## 2. 화면 구성

### 2.1 하단 메뉴바 (BottomNavigationBar)

```
┌──────────┬──────────┬──────────┐
│   홈     │ 업무관리  │  내정보   │
│  🏠     │   📋     │   👤     │
└──────────┴──────────┴──────────┘
```

### 2.2 업무관리 메뉴 화면

```
┌─────────────────────────────┐
│        업무관리              │
│                             │
│  ┌─────────┐ ┌─────────┐   │
│  │ QR생성  │ │안전보고서│   │
│  │  📱    │ │  📝    │   │
│  └─────────┘ └─────────┘   │
│  ┌─────────┐ ┌─────────┐   │
│  │ 작업추가 │ │결재요청 │   │
│  │  ➕    │ │  💰    │   │
│  └─────────┘ └─────────┘   │
└─────────────────────────────┘
```

### 2.3 결재요청 페이지

```
[결재요청 목록] ← FAB(+) 버튼으로 신규 작성
  │
  ├─ 목록 화면 (상태별 탭/필터, 페이징)
  │   └─ 항목 탭 → 상세 화면
  │
  └─ 신규 작성
      ├─ Step 1: 사진 업로드 → OCR 파싱 (로딩)
      ├─ Step 2: 결과 확인/수정 폼
      │   ├─ 현장 선택 (드롭다운)
      │   ├─ 계정과목 선택 (드롭다운)
      │   ├─ 거래처 선택 (드롭다운)
      │   ├─ 거래처명, 계좌정보 (OCR 자동입력, 수정 가능)
      │   ├─ 금액 (공급가액, 부가세, 합계)
      │   ├─ 항목 리스트
      │   └─ 제목/적요
      └─ Step 3: 저장 → 결재요청 버튼
```

## 3. 성공 기준

| ID | 기준 | 검증 방법 |
|----|------|----------|
| SC-01 | 하단 메뉴바 3탭 전환 정상 동작 | UI 테스트 |
| SC-02 | 업무관리 메뉴 4개 아이콘 표시 + 결재요청 진입 | UI 테스트 |
| SC-03 | 사진 촬영/갤러리 선택 → OCR 파싱 → 폼 자동 채움 | 실기기 테스트 |
| SC-04 | 현장/계정과목/거래처 드롭다운 조회 동작 | API 연동 확인 |
| SC-05 | 수정 후 저장 → 서버에 DRAFT 상태로 저장됨 | DB 확인 |
| SC-06 | 결재요청 → 서버에 REQUESTED 상태로 변경됨 | DB 확인 |
| SC-07 | 결재 목록에서 내가 요청한 건 조회됨 | API 응답 확인 |

## 4. 리스크

| 리스크 | 영향 | 대응 |
|--------|------|------|
| OCR 파싱 정확도 낮음 | 사용자 수정 부담 | 모든 필드 수정 가능하게 구현 |
| 현장에서 네트워크 불안정 | 업로드 실패 | 에러 메시지 + 재시도 가능 |
| 이미지 용량 큼 | 업로드 느림 | 업로드 중 로딩 표시 |
| 시뮬레이터 카메라 없음 | 테스트 제한 | 갤러리 선택으로 테스트 |
